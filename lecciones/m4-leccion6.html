4.6 Corregir una mala salida de IA

Módulo 4 · Ejercicio

Objetivo: Practicar la identificación y corrección de errores en código generado por IA.

Objetivos de aprendizaje

Al finalizar esta lección el estudiante será capaz de:

  • Identificar errores en código generado por IA de manera sistemática.
  • Aplicar la checklist de revisión para detectar casos borde no manejados.
  • Proponer mejoras concretas a código generado.
  • Escribir pruebas que validen el comportamiento del código en casos borde.
  • Documentar el proceso de corrección para futuras referencias.

Actividad

Enunciado

Requerimiento (proyecto conductor To-Do, RF-TODO-001): Función que crea una tarea con título, proyecto, prioridad y fecha de vencimiento. El título es requerido (1 a 120 caracteres), la prioridad solo admite Alta/Media/Baja, y el vencimiento no puede ser pasado.

Prompt usado: "Haz una función que cree una tarea con título, prioridad y vencimiento"

Respuesta de IA:

def crear_tarea(titulo, prioridad, vencimiento):
    tarea = {
        "titulo": titulo,
        "prioridad": prioridad,
        "vencimiento": vencimiento,
        "completada": False,
    }
    return tarea

Actividad

Tareas

  1. ¿El código cumple el requerimiento? Identifica problemas
  2. ¿Qué casos borde de la Lección 2.5 no maneja?
  3. ¿Qué corregirías o mejorarías?
  4. ¿Qué pruebas escribirías (caso feliz + borde/error)?

Problemas a identificar

  • No valida título vacío ni longitud máxima
  • No valida prioridad (acepta cualquier valor)
  • No valida vencimiento pasado ni formato de fecha

Solución mejorada

def crear_tarea(titulo, proyecto=None, etiquetas=None, prioridad="Media", vencimiento=None):
    if not isinstance(titulo, str) or not titulo.strip():
        raise ValueError("El título es requerido")
    if len(titulo.strip()) > 120:
        raise ValueError("El título supera 120 caracteres")
    if prioridad not in ("Alta", "Media", "Baja"):
        raise ValueError("Prioridad inválida")
    if vencimiento is not None and vencimiento < hoy():
        raise ValueError("La fecha no puede ser pasada")
    return {
        "titulo": titulo.strip(),
        "proyecto": proyecto,
        "etiquetas": etiquetas or [],
        "prioridad": prioridad,
        "vencimiento": vencimiento,
        "completada": False,
    }

Introducción

En esta lección pondrás en práctica todo lo aprendido sobre revisión de código generado por IA. Te enfrentarás a un escenario real donde la IA produce una respuesta incorrecta o incompleta, y deberás identificar los problemas, proponer correcciones y justificar tus decisiones. Esta habilidad es fundamental para trabajar con IA de manera profesional.

Desarrollo del contenido

Análisis del código generado

El código que la IA generó funciona para el caso básico: una tarea con datos válidos. Sin embargo, un ingeniero profesional debe considerar todos los casos posibles. El error no está en lo que el código hace, sino en lo que no hace.

Casos borde a considerar (ver catálogo oficial en Lección 2.5)

  • Título vacío: Debe rechazar con "El título es requerido", no crear la tarea.
  • Prioridad inválida: Solo Alta/Media/Baja; cualquier otro valor debe rechazarse.
  • Vencimiento pasado: Debe rechazar con "La fecha no puede ser pasada".
  • Título de 121 caracteres: Debe rechazar (máximo 120).
  • Tipos incorrectos: Título no string o vencimiento con formato inválido deben lanzar un error claro.

El proceso de corrección

  1. Identificar: Revisa el código contra la checklist de 8 puntos.
  2. Priorizar: Clasifica los hallazgos en críticos (fallan en producción), mejorables (calidad de código) y aceptables.
  3. Corregir: Implementa las correcciones necesarias.
  4. Verificar: Prueba con casos borde para confirmar que la corrección funciona.
  5. Documentar: Registra qué encontraste y cómo lo solucionaste.

Ejemplos adicionales de correcciones

Ejemplo: Buscar tarea por título

Prompt: "Función que busque una tarea por título en una lista"

Código generado (con errores):

def buscar_tarea(titulo, tareas):
    for tarea in tareas:
        if tarea['titulo'] == titulo:
            return tarea
    return None

Problemas: No valida tipos, asume que todas las tareas tienen campo 'titulo', no maneja mayúsculas ni espacios.

Versión mejorada:

def buscar_tarea(titulo, tareas):
    if not isinstance(titulo, str):
        raise TypeError("El título debe ser un string")
    if not isinstance(tareas, list):
        raise TypeError("tareas debe ser una lista")
    titulo = titulo.lower().strip()
    for tarea in tareas:
        if isinstance(tarea, dict) and tarea.get('titulo', '').lower().strip() == titulo:
            return tarea
    return None

Ejemplo: Importar tareas desde CSV

Prompt: "Función que lea un archivo CSV de tareas y devuelva la lista de tareas"

Código generado (con errores):

import csv
def importar_tareas_csv(archivo):
    with open(archivo) as f:
        return list(csv.DictReader(f))

Problemas: No maneja archivos inexistentes, no especifica encoding, no maneja archivos vacíos, no valida que cada fila tenga título.

💡 Consejo del instructor: Cuando corrijas código de IA, no te limites a hacerlo funcionar. Aprovecha para mejorar la calidad general: nombres de variables, estructura, documentación. La IA te da un borrador; tú eres responsable del producto final.
⚠ Errores comunes:
  • Corregir solo el error reportado: Ignorar otros problemas potenciales en el mismo código.
  • No probar la corrección: Asumir que porque la IA corrigió, ahora funciona correctamente.
  • Sobre-corregir: Añadir complejidad innecesaria "por si acaso" sin entender realmente el problema.

Buenas prácticas

  • ✔ Siempre prueba la corrección con casos borde antes de integrarla.
  • ✔ Documenta cada corrección y su justificación.
  • ✔ Si el código original tiene múltiples problemas, abórdalos de uno en uno.
  • ✔ Usa la checklist de revisión para asegurarte de no pasar nada por alto.
  • ✔ Mantén un registro de los errores recurrentes para ajustar tus prompts futuros.

Resumen

  • El código generado por IA puede funcionar para el caso básico pero fallar en casos borde.
  • La corrección efectiva implica identificar, priorizar, corregir, verificar y documentar.
  • Los casos borde más comunes son: valores vacíos, tipos incorrectos y entradas límite.
  • Siempre prueba las correcciones antes de integrarlas.
  • Documentar el proceso de corrección ayuda a mejorar prompts futuros.
